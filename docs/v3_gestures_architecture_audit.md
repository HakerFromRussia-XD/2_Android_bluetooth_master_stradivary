# Проверка архитектурных границ «Жестов» V3 — C1

Дата: 2026-09-18. Порядок работ задаёт [основной план](ubi4_v3_clean_architecture_plan.md).
Проверка выполнена после переноса создания адаптера из BaseWidgetsFragment.
Пользовательские имена перенесены в экранный UiState в C1.3.3 (ниже). C1 остаётся
открытым по полной аппаратной проверке входа и возврата из 3D-редактора.

## Проверенные пути

| Сценарий | Текущий путь |
| --- | --- |
| Подключение экрана | page_1 → SprGestureFragment → экранный CompositeDelegateAdapter с GesturesTwoSectionDelegateAdapterV3. UBI4 выбирает прежний общий адаптер. |
| Активный жест | GestureSelected → V3GesturesViewModel → SelectGestureUseCaseV3 → V3GesturesRepository. GET при доступном экране выполняет RequestActiveGestureUseCaseV3; UI отображает activeGestureId. |
| Группа ротации | LoadRotationGroupUseCaseV3 подписывается на ответ перед GET и сохраняет прежние интервалы/число повторов. Удаление, выбор в диалоге и перестановка проходят через отдельные UseCase. |
| Раздел и раскрытие коллекции | Action → ViewModel → UseCase → V3AppSettingsRepository. selectedSection и isFactoryCollectionExpanded приходят из UiState; render не записывает предпочтения. |
| Диалоги | Запросы, выбранные ID и одноразовое сообщение лимита принадлежат UiState. Fragment/Host отображают прежние диалоги и передают Action. Имена поступают из снимка UiState, локализация выполняется в UI. |
| Вход в редактор | GestureSettingsRequested → ViewModel → запрос в UiState → прежняя Activity. Подтверждение запуска вызывает UseCase сохранения номера; порядок startActivity → запись сохранён. |
| Состав виджетов | Профиль поступает через UseCase; DataFactoryV3GesturesWidgetsSource и mapper обеспечивают совместимость со старыми структурами. Список принадлежит UiState. Источник в этом шаге не заменён. |
| Отображение | Состояние передаётся адаптеру до swapData. Отложенный render использует последнее состояние и отменяется при уничтожении view. Сам render не вызывает BLE или UseCase. |

Domain не зависит от Android, data, presentation, DataFactory или widget-структур.
ViewModel не обращается напрямую к репозиториям/глобальным stores. Репозиторий
сохраняет существующие кодеки, порядок локального сохранения и отправки пакетов.
Метаданные widget в getItemId нужны прежнему RecyclerView-адаптеру; они не являются
вторым источником текущего значения жеста.

ViewDetached отключает действия и отменяет запросы группы; pending-диалоги и переход
сбрасываются при уходе, смене адреса, блокировке или исчезновении виджета.
После очистки ViewModel поздние действия игнорируются. Повторные одинаковые ответы
группы завершают загрузку. Эти сценарии покрыты существующими тестами.

## Пользовательские имена — C1.3.3 выполнено

Обнаруженный при аудите обход ViewModel устранён. Действующий путь:
V3AppSettingsRepositoryImpl → GetCustomGestureNamesUseCaseV3 → V3GesturesViewModel
→ UiState.customGestureNames → карточки/активный заголовок/группа/диалоги.

V3CustomGestureNames содержит два неизменяемых списка значений существующих
настроек: names для прямого отображения и collectionNames для коллекции. Null
во втором списке означает локализованное имя по умолчанию в UI. Data сохраняет
различия старых читателей при отсутствующем/null MAC, отсутствующем/null имени
и пустой строке. Индексы хранилища — 0–13, ID жестов — 64–77; они не смешиваются.

Имена читаются при формировании состояния: первоначально, при ViewAttached,
обновлениях сессии/параметров и обработке действий, включая открытие диалогов.
Прежнее уведомление onResume покрывает возврат без уничтожения Fragment.
Нет отдельной подписки preferences, новых Action, записей имён или команд от render.
После очистки ViewModel поздние действия и обновления не возобновляют чтение.

GesturesTwoSectionDelegateAdapterV3 больше не получает gestureNameList из Base
и не вызывает CollectionGesturesProvider. Смена снимка обновляет карточки и
названия группы даже при тех же ID; правила выбора, удаления и порядка не меняются.
SprGestureFragment отключает общий loader Base только в V3-ветке. UBI4 продолжает
использовать его и прежние callbacks.

Заводские названия, картинки, порядок и default-имена выделены из общего provider
в GestureCollectionFactory в Android UI. Это один каталог из 28 элементов для
обеих версий, без дублирования ресурсов. Фабрика получает Context и функцию
разрешения пользовательского имени от вызывающего кода; не читает preferences,
MAC или глобальный application context. V3 передаёт значения из UiState.
Прежний CollectionGesturesProvider сохраняет публичные методы и UBI4-предпочтения,
передавая считанные имена той же фабрике. Жест 12 остаётся скрытым; неизвестный ID
по-прежнему даёт Gesture(0).

Повторная проверка C1: в V3 UI нет чтения имён через старый provider/список Base;
UseCase вызывается только ViewModel, domain не содержит Android-ресурсов/модели
Gesture. Общие связи C4/D2 и полный аппаратный сценарий редактора остаются ниже.

## Очистка по результатам проверки

Из GesturesTwoSectionDelegateAdapterV3 удалены parameterIDSet/deviceAddress и
их заполнение в onBind: значения больше не читались обработчиками и не участвовали
в отображении; использовались только диагностическими строками в том же блоке.
Сохранены getItemId, обработчики Action, порядок рендера, ограничения и lifecycle.
Новых классов или правил поведения не добавлено.

## Сохранённые границы следующих этапов

| Связь | Этап / причина |
| --- | --- |
| DataFactoryV3GesturesWidgetsSource, widget mapper и общие генераторы | D2: V3-подготовка UI отделяется без изменения UBI4/iOS. Сейчас не заменяются. |
| Определение версии, фабричная сборка Repository во Fragment, очередь через Activity, общий updateFlow/навигация | C4: подключение к существующей инфраструктуре. Вынесение адаптера не завершает перенос Base/Activity. |
| MainActivity.main в адаптере для ресурсов, размеров и context | C4: оставшаяся зависимость UI от общей Activity; она не используется для записи параметров жестов. |
| Общий UBI4-код диалогов и sendBLERotationGroup в SprGestureFragment/Base | Используется UBI4-адаптером. V3 передаёт Action, не вызывает эти callbacks. Удалять общий код как дубликат V3 нельзя. |
| Импорт/применение профилей через SettingsProfileApplierV3 | Отдельный сценарий применения настроек, не старый обработчик клика экрана «Жесты». В рамках C1 не удаляется. |
| Общий store/кодеки в data и физическое размещение domain в app | D1/D2; публичные KMM/iOS API и парсеры сохраняются. |
| Внутренности редактора и его автоматическая команда открытия пальцев | C5. Полная аппаратная проверка входа/возврата остаётся отдельно незакрытой. |

Прошлая проверка запуска редактора на эмуляторе остановилась на ошибке шейдера;
она не подтверждает полный сценарий. На реальном 00001 вход в редактор не выполняется
автоматически для проверки архитектуры из-за существующей команды движения.

`:app:testDebugUnitTest`, `:app:assembleDebug`, `:app:assembleRelease` прошли
2026-09-18. Выполнены 608 app-тестов без ошибок/пропусков, включая 10 архитектурных,
91 проверку V3GesturesViewModel, 32 проверки V3GesturesRepository и 6 проверок
состава/mapper. Проверки генераторов покрывают STANDARD_V3/INDY3 и ru/en.
Лог: `/tmp/v3-gestures-audit-build-20260918.log`.

Новые тесты на простое удаление неиспользуемых полей не добавлялись. Запуск UI
на эмуляторе не выполнялся. Парсеры, генераторы, DataFactory, shared/iOS, UBI4-пути,
ресурсы и код 3D-редактора в этом шаге не менялись.

На Samsung SM-A065F с реальным 00001 установлена release APK с сохранением данных.

«Позвони мне», «Кулак 2», «Коза», «Ок», «жест №1». Значения совпали до/после обновления.
Телефон возвращён на исходный экран «Датчики». Журнал сбоев не изменился.
Выбор/редактирование жестов и команды движения не выполнялись; аппаратные сценарии
INDY3, UBI4 и полного редактора этим не проверены.

## Проверки после переноса имён C1.3.3

618 app-тестов без ошибок/пропусков, включая 11 архитектурных; debug/release
собраны, Android UI-тесты с обновлённым контрактом состояния скомпилированы.
Проверены оба старых fallback MAC, missing/null/пустые имена, индексы 0–13,
смена устройства и переименование, обновление после возврата, диалоги и запрет
повторного чтения после очистки VM. Каталог проверен на порядок/ID, скрытый жест,
ресурсы и совместимость общего UBI4-provider; фабрика не читает preferences.

Архитектурные проверки теперь запрещают CollectionGesturesProvider и gestureNameList
в V3-адаптерах, старый provider в V3 render и доступ к хранилищам из визуального каталога.
Все 28 записей каталога дополнительно сопоставлены с исходным кодом по ID, ресурсам
строк/изображений и индексам пользовательских имён. DataFactory-источники и mapper
побайтово совпадают с исходным состоянием шага. Shared, парсеры, iOS и 3D-код не менялись.
Лог: `/tmp/v3-gesture-names-final-build.log`.


На Samsung SM-A065F с реальным 00001 проверены все 14 пользовательских подписей,
возврат из Sensors, заводская коллекция, пять строк группы и диалог добавления
(открытие/отмена без выбора и сохранения). Подписи до/после установки совпали;
активный жест «Кулак 2» и группа не изменились. После проверки восстановлены
раскрытая коллекция, выбранная группа и исходный экран Sensors. Новых сбоев нет.
Во время записанных переходов только GET 0x24 и 0x35, без SET. Установленная
release APK совпадает с собранной по SHA-256.

Переименование и возврат из полного редактора проверены на уровне snapshot/VM,
а не аппаратным запуском редактора. Физические UBI4/INDY3 не проверялись; совместимость
provider/каталога UBI4 покрыта unit-тестами. Эмулятор на этом шаге не запускался.
Артефакты: `/tmp/v3-phone-names-*.xml`, `/tmp/v3-gesture-names-phone-live.log`,
`/tmp/v3-gesture-names-phone-crashes-after.log`, `/tmp/v3-gesture-names-installed-apk.txt`.
