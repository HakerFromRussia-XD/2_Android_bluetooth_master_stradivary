# Аудит оставшихся путей iOS V3

Дата аудита: 20.10.2026. Продолжение шагов 113–119 общего плана; проверка исходников
и локальных сборок. 21.10.2026 выполнена частичная проверка на iPhone, описанная ниже;
полная проверка всех аппаратных сценариев не завершена.

## Что исправлено в шаге 120

- Сброс общего списка виджетов перед синхронизацией V3 теперь проходит через
  `Action → DefaultWidgetsListViewModel → ResetWidgetsForSyncUseCaseV3 →
  V3SyncWidgetsRepository → V3SyncRepositoryImpl`.
  Реализация вызывает прежний `UiStateBridge.resetWidgetsState()`, алгоритм
  сброса не скопирован. Наблюдение и сброс используют один repository из DI.
- Применение сброса при первом открытии, смене источника и ручном повторе
  остаётся синхронным. Порядок «сброс → очистка UI-кешей → запрос данных»,
  количество повторов и существующее состояние загрузки сохранены.
  Прежний UI effect сброса оставлен для UBI4.
- Пользовательские имена в списке жестов V3 читает существующий
  `V3GesturesViewModel → GetCustomGestureNamesUseCaseV3 →
  V3CustomGestureNamesRepositoryImpl`. Нового репозитория или кеша нет;
  ключи, значения и выбор текущего устройства не менялись.
- Первое чтение имён по-прежнему инициализирует `GestureService.shared`:
  его init запускает подписки 3D-редактора. Эта native зависимость сохранена
  явно; её нельзя считать устранённой или убирать без проверки редактора.
  UBI4 читает имена прежним способом.

## Оставшиеся границы

1. **Общая проверка на iPhone.** Чтение и навигация проверены в шаге 121;
   отключение, ручное переподключение к V3 00001 и заполнение экранов — в 122–124.
   Ручной повтор синхронизации, запись настроек и редактор пока не проверены.
   Просмотр каталога не подтверждает установку прошивки;
   обновление прошивки пользователь исключил.
2. **Native подключение и отключение.** Сброс виджетов перед подключением V3
   перенесён в шаге 123: BluetoothListViewController → Action → существующая
   BluetoothListViewModel → ResetWidgetsForSyncUseCaseV3 → V3SyncRepositoryImpl.
   Версия определяется по выбранному устройству, без переключения текущего режима
   до сброса; очистка остаётся перед экранными флагами и подключением.
   Отключение V3 подключено в шаге 122: координатор передаёт Action существующей
   StatusBarViewModel, shared DisconnectDeviceUseCaseV3 вызывает native repository,
   затем ViewModel обновляет статус и вызывает ResetWidgetsForSyncUseCaseV3.
   Native repository сохраняет порядок временного запрета автоподключения,
   BLE disconnect и удаления selectedDeviceName. Навигация остаётся в координаторе;
   прежние UBI4/oldLegacy ветки сохранены.
   В шаге 124 подключение V3 проведено через connectionRequested → ViewModel →
   ConnectDeviceUseCaseV3 → native V3DeviceConnectionRepositoryImpl.
   Это переименованный и расширенный репозиторий отключения, второй не добавлен.
   Сохранение имени/истории и активация режима выполняются до native подготовки
   3D-ресурсов и очистки экранного ID; остановка сканирования и connect — после.
   Само сканирование списка, фильтры, сохранённый выбор для автоподключения и
   callback-подписки остаются native; весь scan lifecycle не объявляется перенесённым.
3. **3D compatibility boundary — проверена в шаге 125.** V3 GET/WRITE/RX,
   сторона руки и пользовательские имена уже используют готовые shared UseCase.
   Убрана обратная связь data → GestureService: DI передаёт пакеты напрямую
   существующему BLE-manager через общий V3-отправитель. Неиспользуемый результат
   getDeviceName больше не читается при открытии V3; UBI4-вызов сохранён.
   GestureService.init по-прежнему запускает native наблюдения. Общий fallback
   ParameterProvider остаётся для событий без payload; обычный shared V3 RX
   передаёт непустой по типу String, включая пустую строку, и не требует fallback.
   Lenient JSON → старая модель Gesture — native адаптация рендера: строгий
   shared decoder не сохраняет все её правила NSNumber/zero/clamp. Эти методы
   оставлены побайтно, новые UseCase только ради совместимости не добавлены.
   Наличие такого native моста само по себе не означает неперенесённый V3 GET/WRITE.
4. **Локальные предпочтения UI.** Видимость служебной вкладки, настройка
   отображения загрузки и фильтр BLE-лога используют native UserDefaults.
   Если выделять хранилище, оно остаётся в native data; перенос этих UIKit
   предпочтений в общий domain только ради одинаковых папок не требуется.
5. **Серийный номер.** GET/callback/кеш и серверная подстановка отложены
   пользователем. Не менять вместе с другими TextInput операциями.

BLEController, BLEParser, DataFactory/generatedHardcodeWidgets, UBI4,
by_Misha/by_Radeon, Android ScanActivity/help/AdvancedFragment не переработаны.
Аудит не означает, что весь native iOS теперь зависит исключительно от UseCase.

## Проверка этого шага

- Generic iOS Debug build с текущим shared.framework успешен, без подписи,
  установки и запуска приложения.
- 167 выбранных JVM-тестов: sync repository/ViewModel, app settings,
  gestures ViewModel, архитектура; без ошибок и пропусков. Новый тест проверяет
  очистку прежних контейнеров, повторные reset-события и неизменность device values
  и состояния синхронизации.
- Извлечённые реальные Swift reducer/VM routing/UI reset/retry и методы чтения
  имён дали 16 одинаковых снимков синхронизации и 6 снимков чтения имён до/после.
  Проверены V3/UBI4, mobile source, retry, completed/reopen, смена режима/устройства,
  отсутствие кеширования и прежний момент запуска 3D-подписок.
  Использованы KMM/source/UIKit doubles; это не KMM/UIKit runtime или BLE-проверка.
- Логи, скрипт и дифф шага: `/tmp/ios-v3-final-audit-20261020`.

## Проверка на iPhone — 21.10.2026, шаг 121

- По разрешению пользователя отдельный временный XCTest runner подписан и запущен
  на физическом iPhone «Денис» (iPhone 17). Проверено уже работающее приложение
  3.1.14 (15), подключённое к устройству `00001`, роль «Сервисный инженер».
  Проверяемое приложение не переустанавливалось и не перезапускалось.
- Два завершённых автоматических сценария прошли: `Navigation.xcresult` и
  `DetailsFinal.xcresult`. Первый делает два круга между «Датчиками»,
  «Спецнастройками», «Служебными» и «Жестами», проверяет непустые таблицы и аккаунт.
  Второй проверяет mobile/prosthetic source, равенство всех восьми строк значений
  до/после возврата, разделы коллекции/ротации, имена пользовательских жестов,
  статистику и открытие/отмену каталога Fest H and F с семью файлами.
- Просмотрены снимки экранов. Показаны чувствительность 60, сила/скорость 100,
  сторона руки, роль и статистика 1474 срабатываний. Показатели соединения на
  сохранённых снимках — `00001`/`connected`. Корректность каждого значения
  независимо от устройства и непрерывность графического потока не проверялись.
- Две промежуточные попытки второго сценария остановились на ограничениях самого
  теста: XCTest tap по SwiftUI-сегменту и регистр подписи «отмена». Исправлены только
  временный тест и локатор; финальный сценарий прошёл. Код приложения не менялся.
- Записи параметров, выбор/перестановка жестов, вход в 3D-редактор, движения,
  калибровка, холодный запуск/повторная синхронизация и переподключение не проверены.
  Файлы прошивки не выбирались, подтверждение установки и DFU не запускались.
- Дополнительные наблюдения: на снимках карточки жестов без 3D-моделей;
  рендер нельзя считать подтверждённым этим прогоном. В аккаунте есть строки
  `Unknown 0.0.0`; само по себе это не доказывает регрессию переноса — прежний
  AccountBridge также отображает неизвестные записи. Эти наблюдения не исправлялись
  изменением правил приложения.
- UUID загруженного shared.framework совпал с локальной сборкой шага 120.
  Native dylib отличается от той временной сборки: проверка установленного
  приложения не заменяет проверку идентичности всей native сборки исходникам.
  QA, временный тест, отчёты и снимки: `/tmp/ios-v3-phone-check-20261021`.
