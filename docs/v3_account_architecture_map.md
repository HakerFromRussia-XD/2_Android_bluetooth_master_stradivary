# Аккаунт V3: границы и порядок переноса — C2

Дата карты: 2026-09-18. Исходная проверка C2.0 выполнена по коду.
Реализация и проверки C2.1 описаны ниже. Основной порядок задан в [плане миграции](ubi4_v3_clean_architecture_plan.md).

## Достижимые сценарии

`MainActivityUBI4.showAccountScreen()` выбирает `AccountFragmentMainV3` по
`UiState.isInterfaceV3Activated`, иначе открывает прежний `AccountFragmentMainUBI4`.
Дополнительного разделения STANDARD_V3/INDY3 в этом маршруте нет.

| Сценарий | Реальный экран и источники | Граница переноса |
| --- | --- | --- |
| Главный аккаунт / имя пользователя | `AccountFragmentMainV3`: шифрование serial → token → userInfo → список устройств → сведения выбранного устройства. `Ubi4RequestsApi` находится в shared. | C2: выделить V3 domain/data и экранное состояние; сохранить запросы, локальные ключи и порядок обновлений. |
| Статистика | `AccountFragmentStatisticsV3`: `WidgetState.telemetryGestureCountersFlow`, `UiState.updateFlow`, preferences с именами и GET телеметрии через Activity/BLEController. В V3 пункт включён; в общем адаптере по умолчанию выключен. | **Первый перенос C2.1**: отдельный V3-экран, без серверного профиля и общего Fragment. |
| Сервис | Общий `AccountFragmentCustomerServiceUBI4`: сохранённые главным аккаунтом данные, расчёт гарантии, открытие номеронабирателя. Сетевой запрос при открытии/refresh закомментирован. | C2: переносить только V3-путь; UBI4 и Android-набор номера сохранить. |

| Игры | Общий `AccountGamesFragment`: manifest, состояние установленного приложения, RuStore, запуск/удаление и игровой сервис. | C2: отдельный ограниченный шаг для V3; не перерабатывать общий игровой сервис ради экрана. |

Навигация/координация Activity — C4. |

«Достижения» имеют обработчик и маршрут, но `showAchievementsItem = false`:
скрытый пункт не включаем и его сценарий в C2 не переносим.
«Профили настроек» в SpecialSettings уже относятся к этапу A; это не серверный
профиль пользователя, повторного переноса в C2 нет.

## Первый перенос: AccountFragmentStatisticsV3

Цепочка: Fragment → `V3AccountStatisticsViewModel` → UseCase → Repository.
Обратный путь: данные → ViewModel → `V3AccountStatisticsUiState` → прежний график.
`V3AccountStatisticsAction` передаёт события жизненного цикла. Папки внутри
`versions/v3`: `domain/accountstatistics`, `data/accountstatistics`,
`presentation/accountstatistics`; ручная сборка зависимостей — в `di`.
Фрагмент остаётся на текущем месте.

- Domain: неизменяемые счётчики/ID, правила отбора и сортировки, контракт
  `V3AccountStatisticsRepository`, UseCase наблюдения и запроса статистики.
- Data: адаптация существующего потока и чтения имён, делегирование существующему
  GET телеметрии. Парсер, генератор пакета и общий store не изменяются.
- ViewModel: подписки только через UseCase и владение состоянием экрана.
- UI: локализация названий и преобразование состояния в `GestureUsageChartItem`;
  без preferences, глобальных потоков и вызова BLE. График и разметка сохраняются.

При реализации сохранить следующие особенности исходного Fragment:

1. Один GET при создании view V3; обновление графика само по себе GET не отправляет.
   Не добавлять таймеры, повторы, новые сообщения об ошибке или новые блокировки.
2. Стандартные счётчики сопоставлены ID 0–15; ID 0 и значения ≤ 0 исключаются.
   Лишние стандартные индексы пропускаются. Пользовательские ID — 64 + индекс,
   без нового ограничения длины; учитываются все положительные счётчики.
3. Сортировка: количество по убыванию, затем ID по возрастанию.
4. Неизвестное стандартное имя остаётся `Gesture <id>`; так сейчас отображается
   и ID 12, которого нет в визуальном каталоге. Не добавлять его в коллекцию.
5. Для пользовательских имён есть 15 локализованных defaults (индексы 0–14),
   далее используется default первого жеста. Preferences читаются по каждому
   индексу счётчика; MAC при отсутствии/null — пустая строка, отсутствующее/null
   имя заменяется default, сохранённая пустая строка остаётся пустой.
   `GetCustomGestureNamesUseCaseV3` сейчас возвращает только 14 имён:
   использовать его как полную замену этого чтения нельзя.
6. Поток телеметрии сразу отдаёт текущий снимок; `updateFlow` обновляет подписи.
   Не менять семантику кеша/фильтрации устройства под видом рефакторинга.
   Подписки привязать к жизненному циклу view, проверить повторное создание и
   отсутствие обращений к уничтоженному UI; сохранить существующую частоту GET.

Проверки при реализации: правила ID/сортировки/имён, обновление UiState, повторное
создание view и отсутствие дополнительных запросов, V3ArchitectureTest и сборка.
На реальном Samsung с 00001 — сравнение экрана и возвратов; без выбора жестов.
Аппаратная поддержка статистики INDY3 этим чтением кода не подтверждена.

## Последовательность C2

1. C2.0 — карта маршрутов и границ (выполнено, этот документ).
2. C2.1 — статистика V3, один законченный экран (реализовано и проверено ниже).
3. C2.2 — серверный профиль главного аккаунта, небольшими частями по существующей
   цепочке запросов. Сохранить фоновые загрузки, кеш, текущие Toast/refresh,
   fallback serial, число повторов и общие ключи данных. Прошивку не переносить.
4. C2.3 — V3-состояния «Сервиса» и «Информации о протезе», по одному экрану;
   проверить общих UBI4-потребителей перед каждой правкой.
5. C2.4 — V3-состояние «Игр», отдельно от игрового сервиса и транспорта.

Не исправлять попутно особенности исходного кода. В частности, главный аккаунт
использует запасной serial `FEST-F-06879`, при некоторых ошибках очищает общие
ACCOUNT-ключи, а сервис вычисляет гарантию как год получения + 3. Изменение этих
правил — отдельная задача, не часть архитектурного переноса.


## C2.1 — реализация статистики

AccountFragmentStatisticsV3 теперь передаёт ViewAttached/ViewDetached и отображает
V3AccountStatisticsUiState. Прежние подписки, чтение preferences, прямой вызов
BLEController и фильтрация/сортировка удалены из Fragment.

ObserveAccountStatisticsUseCaseV3 отбирает положительные счётчики и сортирует
V3GestureUsage; RequestAccountStatisticsUseCaseV3 выполняет запрос через контракт
V3AccountStatisticsRepository. Реализация адаптирует исходную телеметрию и
updateFlow, копирует списки и перечитывает имена только используемых слотов.
V3AccountStatisticsChartMapper локализует названия из состояния через существующий
GestureCollectionFactory; график, цвета, разметка и ресурсы остаются прежними.

ViewAttached вызывается один раз в onViewCreated, ViewDetached — в onDestroyView:
сворачивание/возврат без уничтожения view не делает новый GET. Повторное создание
view получает текущий снимок и ровно один новый GET. Очистка VM прекращает подписки
и игнорирует поздние действия. Дополнительные ошибки/индикаторы/повторы не добавлены.

Ручная сборка — V3AccountStatisticsViewModelFactory в di. Там же остаётся связь
с существующим хостом BLE через MainActivityUBI4.mainOrNull, определяемым при запросе;
ViewModel/data не удерживают Activity. Общий транспорт относится к C4.
Общие аккаунтные Fragment, UBI4, shared, парсеры и генераторы в C2.1 не менялись.

## C2.2.1 — сетевая граница серверного профиля

Подготовлены V3AccountProfileRepository и его data-реализация поверх прежнего
Ubi4RequestsApi. Четыре операции: token по serial, пользователь, список устройств,
информация об устройстве. Domain-модели содержат только используемые значения,
без Android, сетевых DTO и serialization; списки и вложенные объекты скопированы.

Сохранены шифрование serial в Dispatchers.Default, заголовок Aesserial (включая
прежний null-результат шифрования), аргументы token/lang/ID, значения по умолчанию
пользователя и неизменные code/message ошибок. CancellationException проходит
наружу. Репозиторий не добавляет повторов и не выбирает устройство: сохраняются
порядок списка, первый совпадающий serial с null ID, порядок/дубликаты/null опций.
Модель протеза пока возвращается без прежнего сокращения названия — это правило
сохранения предстоит перенести в domain вместе с записью данных.

В C2.2.1 репозиторий был подготовлен отдельно от Fragment и проверен тестами.
Подключение выполнено в C2.2.2 ниже; UI вызывает ViewModel, не репозиторий.

Состав следующего на тот момент шага C2.2.2 — UseCase для последовательности и сохранения,
экранные Action/UiState/ViewModel и подключение к AccountFragmentMainV3. При
подключении удалить заменённые requestToken/requestUserData/requestDeviceList/
requestDeviceInfo и сохранение ACCOUNT-ключей из Fragment. Сохранить счётчик
повторов на время жизни view, текущие моменты обновления UI, фоновые загрузки,
кеш, Toast, fallback serial, правила опций и отмену при уничтожении view.
Прошивка и общие дочерние экраны в этот шаг не включаются.

Проверки C2.2.1: `:app:testDebugUnitTest` прошёл — 649 тестов без ошибок и пропусков,
включая 16 новых проверок репозитория и 12 архитектурных. Production-код debug
скомпилирован этой задачей. Лог: `/tmp/v3-account-profile-repository-build.log`.
Тесты используют подменённый API: реальные запросы и запись персональных данных
не выполнялись. APK не переустанавливалась, аппаратная проверка нового рабочего
пути относится к его подключению в C2.2.2.


## C2.2.2 — подключение серверного профиля

AccountFragmentMainV3 передаёт Action в V3AccountProfileViewModel и отображает
V3AccountProfileUiState: заголовок, доступность содержимого, завершение refresh
и прежние Toast. UseCase получает чистые модели через подготовленный сетевой
репозиторий; новый локальный репозиторий сохраняет общие ACCOUNT-ключи и кеш
заголовка в памяти процесса. Сборка зависимостей находится в di.

LoadAccountProfileUseCaseV3 владеет цепочкой token → user → devices → deviceInfo,
повторами и правилами сохранения. V3AccountProfileLoadSession создаётся на view:
сохраняются общий счётчик попыток, token/clientId для перекрывающихся обновлений
и точный первый serial (null ID первого совпадения не заменяется следующим).
При HTTP 500 у token — максимум четыре попытки с исходным post-increment;
повторный refresh в той же view не сбрасывает счётчик. Ошибки следующих запросов
не повторяются и не очищают сведения. Текстовые признаки отмены подавляют Toast
как раньше; реальная отмена корутины проходит наружу.

Сохранены defaults/null, форматирование версий, fallback serial/языка, исходный
substring модели, порядок options с дубликатами, «-» для отсутствующего ротатора
и сохранение старых аккумулятора/напальчников при отсутствии этих options.
Каждый ключ записывается отдельным edit/putString/apply в прежнем порядке.
Очистка всех 11 ACCOUNT-ключей выполняется только при окончательной ошибке token.

Из Fragment удалены четыре сетевых метода, шифрование, retry counter, модели API,
сохранение manager/device info и static cachedProfileItem. Отображение не делает
сетевые запросы; после размещения заголовка в очереди UI его подтверждение
сохраняет лишь кеш заголовка через ViewModel/UseCase. Новая view отменяет работу
прежней; запоздалые ответы/отложенный старт/рендер старой view не обновляют экран.
При обычном STOP загрузка не перезапускается, как в исходном lifecycleScope.

Общие дочерние экраны и UBI4-путь не изменены. Методы списка плат, прошивки,
навигации и видимости сервисных кнопок сравнены с копией до шага — совпадают.
Они остаются отдельными обязанностями C4/C5; весь AccountFragmentMainV3 пока
не является полностью перенесённым экраном. Общий Rx-сигнал обновления заголовка
сохранён и передаёт Action. Парсеры, генераторы, shared/iOS и ресурсы не менялись.

## C2.3.1 — «Служба поддержки» V3

Общий `AccountFragmentCustomerServiceUBI4` выбирает V3-путь по существующему
`UiState.isInterfaceV3Activated`. V3 отображает `V3CustomerServiceUiState` и передаёт
Action экранной ViewModel; UBI4 сохраняет прежнее чтение и общий список адаптера.
Для V3 список поступает в адаптер явно, без обращения к этому общему списку.

Повторно используется `V3AccountProfileLocalRepository`: добавлено чтение деталей
по тем же ACCOUNT-ключам, что используются при сохранении профиля. Новый репозиторий
не вводился; сопоставление ключей едино для чтения и записи.
`GetCustomerServiceInfoUseCaseV3` сохраняет прежний строковый расчёт гарантии (+3 года),
включая требования к входной дате. Номер менеджера перечитывается отдельным UseCase
при нажатии; Fragment выполняет прежний ACTION_DIAL, без автоматического звонка.
Отображение не записывает данные и не запускает запросы. Pull-to-refresh, как прежде,
только завершает анимацию; возврат из номеронабирателя не перечитывает карточку.

Проверены 698 app-тестов без ошибок/пропусков, включая 14 архитектурных; debug/release
собраны. Добавлены проверки расчёта даты, ключей/default «null», актуального номера,
жизненного цикла и независимости источников адаптера V3/UBI4. Проверка Android View
выполнена на телефоне; JVM-проверки адаптера ограничены выбором источника списка.
На Samsung R8YX900N0JK с реальным 00001 установлен release: тексты и координаты
экрана совпали до/после, номер в номеронабирателе совпал; проверены возврат,
обновление и повторное открытие. Журнал crash не изменился. Звонков и команд
движения не выполняли. Физические UBI4/INDY3 в этом шаге не проверялись.
Шаг C2.3.2 выполнен ниже; следующий — C2.4, «Игры» V3.


## C2.3.2 — «Информация о протезе» V3

`AccountFragmentProsthesisInformationUBI4` выбирает V3-путь по существующему флагу
интерфейса. ViewModel получает шесть характеристик через
`GetProsthesisInformationUseCaseV3` и существующий `V3AccountProfileLocalRepository`.
Fragment отображает UiState; адаптер V3 получает список явно. Прежние чтения
