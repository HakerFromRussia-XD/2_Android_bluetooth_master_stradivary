# C5.1 — карта редактора жестов V3

Карта C5.1 составлена по коду 2026-09-21; исходное поведение описано ниже.
Результат реализации C5.2.1 приведён в конце; позиции пока не перенесены. Основной файл:
`app/src/main/java/com/bailout/stickk/ubi4/ui/gripper/with_encoders_v3/UBI4GripperScreenWithEncodersActivityV3.kt`.
Ни production-код, ни тесты в C5.1 не изменены; редактор на протезе не открывался.

## Вход и общие потребители

- SprGestureFragment.openV3GestureSettings запускает Activity с
  EXTRA_USE_V3_GESTURE_PROTOCOL=true, parameterID=dataCode из registry и gestureId.
  Сразу после startActivity отправляет GestureSettingsOpened: прежний номер жеста
  сохраняется через экранную цепочку. Редактор читает этот номер из preferences.
- BaseWidgetsFragment.showGestureSettings запускает ту же Activity с флагом false
  и адресом/параметром/ID для UBI4. По умолчанию флаг Activity равен true.
  Имя Activity не доказывает, что экран принадлежит только V3.
- Renderer читает углы, флаги анимации и сторону из companion Activity. Эти поля
  использует также UBI4GripperV3ModelTestActivity. Их удаление не входит в первый шаг.
- Renderer имеет источник позы и режим без событий пальцев для превью коллекции.
  Общие renderer/GLSurfaceView, V3FingerPositionMapping и загрузку модели сохраняем.

## Фактическая последовательность

| Событие | Текущее поведение, которое сохраняем |
| --- | --- |
| Создание | Номер из SELECT_GESTURE_SETTINGS_NUM (default 0), адрес/parameter/gestureId из Intent. Имена индексируются номером минус один. Сторона V3 из ParameterStore, при отсутствии — прежние preferences. |
| Чтение | launchWhenStarted ожидает первый BLEState.READY, затем requestGestureInfo через MainActivity. Повторного явного запроса при каждом onResume нет. |
| Ответ V3 | Парсер обновляет store/ParameterProvider и публикует Rx-событие. Activity читает сериализованный ParameterProvider, декодирует GestureV3. На этом уровне нет фильтра по ожидаемому ID. Ошибка декодирования вызывает прежний toast. |
| Ответ UBI4 | Отдельный Rx-поток и ParameterProvider.getParameter(address,id), Gesture преобразуется в GestureV3. Этот путь остаётся прежним. |
| Первое отображение | Загрузка данных и первый GL-кадр могут прийти в любом порядке. Только после обоих startInitialTransitionIfReady запускает OPEN с sendBleCommand=true. Флаг старта выставляется до postOnAnimation; callback проверяет finishing/destroyed. |
| Позиции | Пальцы UI 1–4 соответствуют позициям пакета 4–1; 5–6 — двум осям большого пальца. Позиции при чтении/сборке ограничиваются 0..100. Rx renderer меняет выбранную открытую/закрытую позу и вызывает отправку. |
| Большой палец | Событие 5 перезапускает Handler на 12 мс; событие 6 отменяет его и отправляет сразу. Объединение этих событий не заменять общим debounce произвольной длительности. |
| Открыть/закрыть | Перед анимацией отправляется состояние 128/129, затем локальное состояние становится 0/1. Анимация не должна заново отправлять команду при каждом render. |
| Задержки | Диалог выбирает openToClose при gestureState=1, иначе closeToOpen. onProgressChanged обновляет подпись, onStopTrackingTouch сохраняет значение и отправляет команду. Закрытие диалога не откатывает сделанные записи. |
| Каждая V3-отправка | Создать Gesture → ParameterStoreV3.put → SettingsProfileManager.saveBleValue → BLECommandsV3.sendGestureInfo → очередь SERIALPORTCHAR_UUID/WRITE. Сохраняется весь жест, не только изменённый палец. |
| Сохранить | gestureState=255 → compileBLEMassage → при редактировании имени записать имя и emit updateFlow(0) → finish. Завершения BLE-записи/ACK экран не ждёт. |
| Назад | В Activity нет своего обработчика отката. Уже отправленные изменения не являются отменяемым черновиком. Поведение родительского BaseActivity сохраняется. |

BLECommandsV3 не включает имя в пакет настроек жеста. Имя хранится локально.
Не менять порядок команд, кодек, диапазоны, retry, проверки ID или поведение
«Назад» как попутное исправление при переносе.

## Имя жеста — первый законченный перенос C5.2.1

Сценарий не требует переноса renderer или протокола позиций:
отображение имени → начало ввода → изменение текста → подтверждение;
также сохранение введённого имени общей кнопкой «Сохранить».

- Одна экранная V3GestureEditorViewModel, V3GestureEditorUiState/Action в
  presentation/gestureeditor; далее эту же ViewModel расширяем для позиций.
  Не создавать отдельную ViewModel на имя и цепочки Controller/Host/Executor.
- Чтение/запись локальных настроек через UseCase и существующий
  V3AppSettingsRepository/Impl в appsettings, сборка — di.
  Нужен отдельный метод чтения данных редактора: существующий
  getCustomGestureNames имеет другие defaults (NOT SET! и пустой MAC).
  Механическая подмена им изменит поведение.
- Сохранить исходные defaults редактора: чтение MAC/имени — "load not work",
  MAC при записи — "text". При подтверждении переписывается весь загруженный
  список, каждый ключ через отдельный apply; затем updateFlow.tryEmit(0).
  Не заменять это записью одного имени или новым правилом валидации без запроса.
- ViewModel хранит отображаемое имя, текст ввода и режим редактирования.
  Activity отображает состояние, передаёт Actions, управляет клавиатурой/фокусом.
  Ввод не должен сбрасываться повторным render или отправлять BLE-команды.
- Общая кнопка пока сохраняет позу прежним путём, затем подтверждает имя через
  Action и завершает экран в прежнем порядке. Это временная явная граница;
  весь редактор после этого не объявляется перенесённым.
- UBI4 сохраняет текущие обработчики. Удаляем заменённые V3-обращения к preferences,
  но не общую реализацию, которой продолжает пользоваться UBI4.

Проверки первого переноса: исходные defaults и индексы; вход/подтверждение ввода;
пустое имя без новых ограничений; запись списка и updateFlow в прежнем порядке;
общая кнопка с активным/неактивным вводом; отсутствие записей при render;
нет изменения V3 BLE-пакета и UBI4-ветки; архитектурные app-тесты и сборки.
Невалидный номер жеста — существующая опасная граница, а не разрешение молча
добавить clamp или выбрать другой жест.

## Lifecycle и ограничения проверки

GLSurfaceView получает onResume/onPause. onDestroy отменяет ValueAnimator,
сбрасывает флаги анимации, удаляет Handler callbacks и listeners первого/следующего
кадра. Rx подписки настроек и углов используют bindToLifecycle; обработчики кнопок
не содержат этого compose. Отмена Handler на STOP в текущем коде отсутствует.
Не переносить сюда механически политику STOP других экранов: это меняет время
отправки. Отдельно сверить существующий lifecycle с требованиями V3 до реализации
позиций; проблему не исправлять скрыто под видом переноса.

Существующие тесты V3FingerPositionMappingTest/CollectionGestureClipTest покрывают
отдельные расчёты, не полный редактор. Текущая Activity не сохраняет своё состояние
через onSaveInstanceState; новая retained ViewModel не должна незаметно вводить
иное восстановление или повторять команды. Ошибки загрузки, смена устройства,
пересоздание и запоздалые события требуют сравнения старого/нового поведения.

В этом шаге сборки/тесты не запускались: изменена только карта и план.
UBI4, Advanced, iOS, парсеры, команды и общая отрисовка не редактировались.

## C5.2.1 — имя жеста подключено к ViewModel

V3GestureEditorViewModel владеет именем, вводом и режимом редактирования.
Activity передаёт EditNameClicked/NameChanged/SaveNameRequested и отображает
UiState; клавиатура/фокус остаются UI. GetGestureEditorNamesUseCaseV3 и
SaveGestureEditorNamesUseCaseV3 используют существующий V3AppSettingsRepository.
Его реализация сохраняет defaults редактора, номер минус один, прежние ключи,
запись всего списка отдельными apply и updateFlow(0) после записей.
Сборка зависимостей — V3GestureEditorViewModelFactory.

Старая ветка имени теперь вызывается только UBI4. У V3 больше нет чтения/записи
имён напрямую из Activity. Оставшееся чтение preferences для стороны руки и
BLE-логика относятся к следующим частям и не считаются перенесёнными.
Общая кнопка сохраняет позу прежним путём, затем передаёт SaveNameRequested,
затем finish; подтверждение имени кнопкой редактирования завершает режим ввода,
а общая кнопка не переключает его перед закрытием. Пакет использует прежнее
подтверждённое имя; сам кодек V3 имя в пакет не включает.

ViewCreated заново читает сохранённые имена при пересоздании Activity, как раньше;
ViewDestroyed/очистка VM запрещают последующие действия. XML с maxLength=12,
пустые строки и пробелы сохранены; новых ограничений имени/индекса нет.
Старый обработчик UBI4 сравнен с исходным без учёта отступов; методы чтения BLE,
сохранения позиций, загрузки позы и запуска переходов совпали дословно.

Добавлены 7 проверок: чтение/defaults и порядок записи/уведомления в data,
подтверждение ввода и сохранение остальных имён, пустое имя общей кнопкой,
пересоздание, очистка ViewModel и прежняя ошибка недопустимого номера.
Аппаратное переименование пока не проверено: вход в редактор запускает движение.

согласования первого кадра и начальной команды OPEN.

## C5.2.2 — загрузка настроек редактора V3

V3GestureEditorRepositoryImpl наблюдает прежний Rx-поток, читает ParameterProvider
на том же Android main scheduler и декодирует GestureV3. В domain передаются
значения без Android/Rx/сериализации: ID и четыре списка по шесть значений
в порядке устройства. Ошибка/пустой ответ сохраняется как отдельное событие.
ID не фильтруется; записи store, кодек и парсер не изменены.

ObserveGestureSettingsUseCaseV3 передаёт ответы экранной ViewModel.
RequestGestureSettingsUseCaseV3 ожидает READY и запрашивает настройки существующим
BLECommandsV3/transport. Activity сообщает STARTED/STOP через repeatOnLifecycle.
STOP отменяет только незавершённое ожидание запроса; после следующего STARTED
ожидание возобновляется, уже отправленный запрос не повторяется. При DESTROY
и очистке ViewModel отменяются обе подписки. Пересоздание начинает новый цикл,
как прежняя Activity; автоматических retry и новых правил ID нет.

UiState хранит loadedSettings и очередь неприменённых ответов с ID. Очередь нужна,
чтобы StateFlow не склеил ответы или одинаковые ошибки: каждый ответ применяется
и подтверждается SettingsApplied. Изменение имени не переустанавливает позиции.
Результаты принимаются и отображаются до DESTROY, включая STOP, как прежняя Rx
подписка; их не заменяли подпиской, активной только в STARTED.

ViewModel согласует RendererReady и первое успешное SettingsApplied и выдаёт
однократный initialOpenRequested. Activity подтверждает обработку перед прежним
postOnAnimation. В callback сохранены проверки finishing/destroyed. Из render
позиций удалён V3-вызов начального открытия; исполнение однократного запроса
пока использует прежний startFingerTransition/sendBleCommand. Это временная
граница до C5.2.3, а не завершённый перенос отправки позиций.

Прежняя локальная редактируемая поза остаётся в Activity; UiState.loadedSettings
представляет последний полученный ответ, не весь текущий черновик редактирования.
Преобразование порядка пальцев, ограничение позиций 0..100, анимации, диалог
задержек, сохранение профиля, 12 мс большого пальца и команды записи не изменены.
Обработчик ответа UBI4, методы записи/сохранения, переходов и диалога задержек
сравнены с исходными: совпадают дословно; в loadGestureState меняется только
условие запуска начального перехода (он остаётся там для UBI4).

Добавлены 10 тестов data/ViewModel: исходный пакет запроса; ожидание READY;
все позиции/задержки, ошибки и отмена Rx; оба порядка данных/кадра, повторные
ответы/подтверждения, STARTED/STOP, DESTROY/очистка и пересоздание. Первый прогон
выявил отсутствие параметра в реестре тестового устройства; исправлена подготовка
теста, реальная логика ParameterProvider не менялась.

Аппаратная проверка редактора остаётся открытой: вход отправляет команду движения.
Следующий C5.2.3 — перенести редактируемую позу, действия и записи через domain/data,
удалив заменённую V3-логику из Activity. UBI4, renderer, iOS и парсеры сохраняются.

Проверка C5.2.2: 787 app-тестов, 0 ошибок/падений/пропусков, debug/release
собраны. Лог: `/tmp/v3-editor-load-verified-build.log`. APK на телефон в этом
шаге не устанавливался; физические V3/INDY3/UBI4 и движения не проверялись.

## C5.2.3 — редактируемая поза и запись жеста

V3GestureEditorUiState.settings теперь владеет редактируемой позой и задержками,
command — текущим режимом команды. EditGestureSettingsUseCaseV3 сохраняет
прежние правила: при загрузке позиции ограничиваются 0..100, ID остаётся из
Intent; позиции первых четырёх пальцев при редактировании остаются исходными,
оси большого пальца ограничиваются сразу. WriteGestureSettingsUseCaseV3
ограничивает все позиции перед записью, задержки не преобразует.

ViewModel принимает изменения пальцев, задержек, начало переключения позы и
SaveClicked. Пальцы renderer 1–4 отображаются в индексы устройства 3–0; задержки
сохраняют исходный порядок. Пятый канал перезапускает отложенную отправку на
12 мс, шестой отменяет её и пишет сразу. Другие действия не отменяют ожидание:
его callback читает актуальную позу/команду/имя. STOP сохраняет это исходное
поведение; DESTROY, пересоздание и очистка VM отменяют ожидающую отправку.
Это сохранение логики редактора по прямому требованию пользователя, а не
применение отличающейся политики STOP с других экранов.

Repository выполняет прежнюю последовательность ParameterStoreV3.put →
SettingsProfileManager.saveBleValue → BLECommandsV3.sendGestureInfo → transport.
Команды сохранены: OPEN=0, CLOSE=1, OPEN_WITH_DELAY=128,
CLOSE_WITH_DELAY=129, SAVE=255. Запись SAVE предшествует сохранению имени;
closeRequested закрывает Activity без ожидания ACK или отложенного канала.
Прежний отдельный SaveNameRequested удалён: общая кнопка имеет один Action.

Из Activity удалён persistGestureSettings и V3-ветка compileBLEMassage.
Старые handlers, Handler для большого пальца и BLECommands остаются только
для UBI4. Общая анимация сохранена; её текущие промежуточные позиции/score
принадлежат UI, а поля целей V3 заполняются из состояния ViewModel и не
сохраняют данные сами. Начальный OPEN использует ту же цепочку Action/UseCase.
Новых Controller/Host/Executor нет; добавлены два UseCase в существующие слои.

Проверки записи охватывают оба положения, все команды и поля пакета, порядок
store/профиль/очередь, ошибку сохранения, перестановку пальцев, повторные значения,
12 мс и отмену шестым каналом, изменение команды во время ожидания, SAVE до
записи имени, STOP/DESTROY/очистку/пересоздание и сохранение выбранного ID.
UI и протокол не переработаны; аппаратное выполнение движений не проверялось.
Далее C5.2.4 — сверка оставшегося чтения стороны руки, общих связей и lifecycle.

Проверка C5.2.3: 801 app-тест, 0 ошибок/падений/пропусков; debug/release собраны.
Лог: `/tmp/v3-editor-write-final-build.log`. По сравнению с HEAD неизменны
UBI4-обработчики пальцев и ответов, обработчики задержек после V3-dispatch,
расчёты анимации и загрузки. Activity стала на 8 строк короче; в production
добавлены только два UseCase, остальные изменения — в существующих классах.
APK не устанавливался; движения, физические V3/INDY3/UBI4 и работа GPU
в этой проверке не тестировались. Это не завершение аппаратной приёмки C1/E.

### Дополнительная проверка C5.2.3 на Samsung — 2026-09-21

После запроса пользователя проверить телефон установлена собранная release-версия
на Samsung SM-A065F (R8YX900N0JK), подключён реальный V3 `00001`.
