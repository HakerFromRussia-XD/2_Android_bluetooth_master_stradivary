## Context

См. `proposal.md` — Why. Сейчас общий bridge скрывает распознанный префикс для UI, но перед отправкой безусловно добавляет префикс активного профиля. Поэтому имя, уже полученное без префикса, самопроизвольно становится prefixed после редактирования. Android и iOS используют результат форматирования одновременно как BLE payload и новое локальное имя. Android stack trace дополнительно относится к старой реализации touch-prefill: `setText()` запускал byte-limit watcher, после чего `setSelection()` мог использовать длину строки до обрезания.

## Goals / Non-Goals

**Goals:**

- Иметь одно общее правило нормализации исходящего имени для Android и iOS.
- Сохранить наличие или отсутствие префикса в текущем полном имени устройства.
- Не менять существующее восстановление семейного префикса для имён, полученных с распознанным префиксом.
- Передавать, сохранять и немедленно показывать согласованное итоговое значение.
- Сохранить лимит изменяемой части имени в 13 UTF-8 байт и свободное перемещение Android-курсора.

**Non-Goals:**

- Определять профиль V3/INDY3 по произвольному имени после нового сканирования.
- Добавлять постоянное сопоставление Bluetooth address/UUID с профилем устройства.
- Изменять отображение и запись виджета серийного номера.
- Менять существующий выбор конкретного семейного префикса для prefixed-режима.

## Decisions

### 1. Общий bridge формирует имя из изменяемой части и текущего полного имени

В commonMain заменить API, который безусловно обещает добавление префикса, операцией с двумя входами: введённым значением и текущим полным именем устройства. Операция выполняет trim окружающих пробелов, удаляет распознанный префикс из введённого значения, если пользователь ввёл его вручную, и отклоняет пустую изменяемую часть.

Затем операция проверяет текущее полное имя через существующий классификатор:

- при наличии распознанного префикса используется существующее правило восстановления префикса активного профиля;
- при отсутствии распознанного префикса возвращается только нормализованная изменяемая часть;
- при отсутствии доступного текущего полного имени выбирается безопасный prefix-free режим, чтобы приложение не добавляло данные, которых не получало от устройства.

Режим определяется не по активному профилю и не по отображаемому тексту: профиль остаётся необходимым только для выбора префикса внутри уже подтверждённого prefixed-режима. Это сохраняет прежнее поведение V3/INDY3 с префиксом и исправляет только случай, когда устройство передало имя без него.

Альтернатива — хранить отдельный boolean `hasPrefix`. Она отклонена как избыточное дублирование: полное текущее имя уже является источником истины и обновляется после записи.

### 2. BLE payload становится новым полным текущим именем

Android передаёт результат общей операции в построитель команды и в `applyDeviceNameImmediately`. iOS использует тот же результат для команды, key-value storage и уведомления заголовка. Ни одна платформа не формирует второе локальное представление для хранения.

После отправки точное итоговое значение становится новым текущим полным именем. Поэтому запись без префикса переводит последующие редактирования в prefix-free режим, а запись с префиксом сохраняет prefixed-режим. Для отображения по-прежнему используется отдельная операция удаления распознанного префикса.

### 3. Платформы передают bridge полный источник имени

Android использует полное имя из текущего connection/activity state, применяемое и для немедленного обновления после отправки. iOS использует полное значение `selectedDeviceName`, сохранённое при выборе устройства и обновлённое после отправки. Текст из поля не может быть источником режима, поскольку UI намеренно скрывает префикс.

Если несколько источников Android-состояния доступны, приоритет остаётся у актуального имени текущего соединения, а не у форматированного заголовка или текста поля. Это не требует нового постоянного хранилища профиля.

### 4. Android prefill не зависит от touch/click

Поле заполняется один раз при bind. После фактического `setText()` курсор устанавливается по длине текущего `Editable`. Touch/click listeners не выполняют повторный prefill, поэтому стандартный `EditText` самостоятельно обрабатывает позиционирование курсора.

Ограничитель сохраняет максимум 13 UTF-8 байт для изменяемой части и обрезает только по границам полных Unicode code point. Префикс, восстановленный после ввода, не входит в этот лимит, что соответствует текущему контракту.

### 5. Классификация после переподключения не расширяется

Активный профиль известен до завершения текущего соединения. Если устройство уже рекламирует prefix-free имя, классификация только по BLE-имени может не определить V3/INDY3 при новом сканировании. Надёжное решение требует отдельной идентичности по address/UUID и выходит за рамки этого изменения.

## Risks / Trade-offs

- [Платформа передаст отображаемое имя вместо полного] → Общий API требует явный параметр текущего полного имени; тесты проверяют оба режима на одном активном профиле.
- [Локальное состояние не обновится после prefix-free записи] → BLE payload и обновление состояния используют одну переменную; повторное редактирование покрывается регрессионным тестом.
- [Prefix-free устройство не пройдёт фильтр «наши устройства» после переподключения] → Ограничение явно остаётся вне scope; при необходимости отдельно спроектировать профиль по address/UUID.
- [Пользователь вручную введёт известный префикс] → Общая нормализация сначала удаляет его, а затем применяет режим текущего полного имени.
- [Старый APK продолжит падать на касании] → Собрать и установить свежий APK, затем убедиться, что touch-prefill отсутствует.
- [Многобайтовый символ будет разрезан на границе лимита] → Сохранить обрезание по полным Unicode code point/Character и соответствующие тесты.

## Migration Plan

1. Обновить общий контракт форматирования и его тесты для prefixed и prefix-free режимов.
2. Передать текущее полное имя в общий bridge на Android и iOS.
3. Использовать единый итог как BLE payload и новое локальное полное имя.
4. Собрать свежие приложения и проверить оба режима на стандартном V3 и INDY3.
5. Для отката вернуть безусловное добавление префикса активного профиля; формат BLE-команды и хранилищ не меняется.
