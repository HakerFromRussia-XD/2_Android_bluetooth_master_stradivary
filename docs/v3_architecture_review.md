# Ревизия перенесённой архитектуры V3 — 2026-09-21

Актуализация 2026-09-22: [повторный аудит всей нативной части app](app_native_architecture_audit.md)
и очередь R0–R8 в основном плане имеют приоритет над прежними «следующими шагами»
ниже. Подтверждены оставшиеся прямые пути адаптеров, SettingsProfileApplierV3 →
MainActivity, Dashboard, часть аккаунта и общие scan/intro. Чистота всего app
не подтверждена. Цифры 202 файлов и этапы ниже относятся к предыдущей ревизии;
сейчас versions/v3 содержит 235 Kotlin-файлов. C5.2.4 уже выполнен в коде,
аппаратная приёмка редактора остаётся отдельной задачей.

Вывод: основные границы перенесённых экранов соблюдаются, но миграция проекта
не завершена. Очередь/worker и состояние синхронизации V3 вынесены из Activity.
C5.2.1–C5.2.3 перенесли имя, загрузку, редактируемую позу и запись жеста через
ViewModel/UseCase/Repository. Далее C5.2.4 — оставшиеся зависимости редактора
и lifecycle. Остатки C4 перечислены в D2/C5; C4 целиком открыт.
Это архитектурная ревизия и точечный рефакторинг, не доказательство отсутствия
всех ошибок и не завершение KMM/3D/DFU.

## Область проверки

Инвентаризация 202 Kotlin-файлов versions/v3: domain 112, data 16,
presentation 64, di 10. Проверены зависимости слоёв архитектурными тестами,
потребители объявленных классов и точные повторяющиеся блоки. Прослежены
основные цепочки настроек, графика/порогов, жестов, профилей, аккаунта и игр;
проверены подключения четырёх основных Fragment, адаптеров, Base и BLE.
Проверка зависимостей всех файлов не равнозначна построчной проверке каждого
возможного поведения. Advanced и его binding исключены пользователем.

## Что подтверждено и что исправлено

- Domain не импортирует Android, BLE, data, presentation или DI. Контракты
  репозиториев и правила находятся здесь; короткие UseCase не удалены ради метрик.
- ViewModel обращаются к UseCase, предоставляют read-only UiState и onAction.
  StateHolder не вызывает Repository/UseCase. Удалять Action/UiState ради меньшего
  числа файлов было бы нарушением согласованной структуры MVVM + MVI.
- Fragment наблюдает состояние через lifecycle и передаёт действия; диалоговые
  Host управляют Android UI, не заменяют ViewModel. Их наличие само по себе
  не является лишним слоем.
- В V3DeviceSettingsRepositoryImpl три одинаковых последовательности
  store → профиль → сериализованный cache объединены в saveTypedValue.
  Порядок отправки команды и ранние выходы сохранены. Нового класса нет.
- В V3SpecialSettingsViewModel четыре повторения обновления Slider → ToggleSlider
  → Spinner заменены одним приватным методом с тем же порядком вызовов.
- Удалены дубли импортов Service ViewModel. Рабочий код сокращён на 11 строк.
- Архитектурные ограничения расширены на общую ubi4.di и UI в data, а также
  общую DI в presentation. Прежние проверки не ослаблены.
- В AGENTS.md закреплены SOLID/KISS/DRY и запрет обёрток без самостоятельной
  ответственности. Нет новых production-файлов или универсальных базовых классов.
- Полностью неиспользуемых объявленных классов по поиску production-ссылок
  не найдено. Наличие ссылки само по себе не доказывает достижимость сценария.

## Оставшиеся архитектурные границы

| Участок | Состояние / дальнейшее действие |
| --- | --- |
| Спецнастройки, датчики, служебные настройки | A/B завершены в рамках Android-миграции; UI-состав пока имеет совместимость с DataFactory. |
| Жесты | Основные действия перенесены; C1 остаётся открыт из-за полного аппаратного сценария редактора. |
| Аккаунт, статистика, сервис, информация, игры | C2 завершён по плану; удалённые сервисы не перепроверялись в этой ревизии. |
| Activity | write/reset/уведомление и очередь/worker/счётчик вынесены. Состояние синхронизации перенесено. Навигация остаётся UI; данные шапки, startup/session, телеметрия — D2, DFU — C5; C4 открыт. |
| BaseWidgetsFragment | Сохраняет общие и исключённые пользователем пути; нельзя удалить их как «дубли V3» без учёта UBI4/Advanced. |
| DataFactoryV3*WidgetsSource | Явная временная совместимость с общим составом виджетов; устранение относится к D2. |
| ParameterStore/ParameterProvider/FlagState | Изолированы не полностью на уровне всей системы; data использует прежние хранилища, BLE сохраняет глобальный флаг. Не выдавать это за окончательную архитектуру. |
| Крупные экранные ViewModel | SpecialSettings — 633 строки, Service — 421. Сложность требует контроля, но дробление на классы, вызывающие UseCase вместо VM, запрещено. |
| 3D и прошивка | C5 впереди; не менять протокол и правила восстановления под видом рефакторинга. |
| KMM | D впереди: выделенный domain пока в app, совместимость shared/iOS отдельно. iOS не редактировать. |
| Финальная приёмка | E впереди; навигация обычного V3 не заменяет проверку INDY3, UBI4, сохранений, 3D и прошивки. |

Порядок после сверки C4.27: C5 → D → повторная сверка остатков C4 → E. Для следующего переноса сначала определить
самостоятельную ответственность и удалить старую реализацию; не создавать
фабрики/посредники лишь для перенаправления вызовов. Процент «чистоты» не используется:
проверяются конкретные границы и завершённые сценарии.
