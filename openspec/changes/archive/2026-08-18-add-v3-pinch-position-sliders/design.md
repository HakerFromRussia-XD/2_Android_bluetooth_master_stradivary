## Context

См. мотивацию в `proposal.md` и поведенческий контракт в `specs/v3-pinch-position-settings/spec.md`.

V3-виджеты формируются в `commonMain`, после чего Android и iOS отображают один и тот же `SliderParameterWidgetSStruct` своими существующими V3-компонентами. Типизированные значения проходят через `ParameterInfoRegistry`, `ParameterCodecRegistryV3`, `ParameterStoreV3` и `WidgetResponseRoutesV3`; запись платформы выполняют через общий `WidgetCommandBridgeV3`/V3-командный формат. Списки init-запросов пока собираются отдельно в Android `BLEController` и iOS `BleManagerKmm`, а standard V3 и INDY3 имеют раздельные генераторы виджетов и init-последовательности.

Существующий scalar-кодек слайдера читает один байт значения после subcommand, а `BLECommandsV3.sendCommand` записывает scalar в один байт короткого пакета. Это соответствует предполагаемому контракту новых команд и диапазону `0…100`, однако его нужно подтвердить интеграционной проверкой с актуальной прошивкой.

Firmware сохраняет исторические имена команд `PINCH_*`, но их фактическая семантика глобальна: значения задают закрытое положение большого пальца и общей пары указательного/среднего пальцев для всех жестов. Доменная модель и UI не должны наследовать вводящую в заблуждение привязку к «Щёпоти».

## Goals / Non-Goals

**Goals:**

- Описать каждый параметр положения пальцев один раз в общем протокольном/доменном слое и переиспользовать его на обеих платформах.
- Встроить параметры в существующий V3 slider pipeline без отдельных Android- и iOS-виджетов.
- Сохранить независимую адресацию, состояние и запись двух значений.
- Хранить одну глобальную пару значений, не зависящую от активного жеста.
- Явно удержать границу профиля: изменения относятся к standard V3 и не попадают в INDY3.

**Non-Goals:**

- Добавление отдельных значений для каждого жеста или изменение существующих настроек самих жестов и 3D-модели руки.
- Управление закрытым положением безымянного пальца и мизинца.
- Изменение прошивки, формата V3-пакета, общего UI слайдера или legacy-протокола.
- Добавление знака `%`, справочных карточек либо отдельного экрана.
- Перестройка всей существующей системы init-запросов.

## Decisions

### 1. Представить параметры как два независимых общих V3 scalar-slider metadata entry

Для параметров вводятся отдельные стабильные нейтральные доменные ключи, пары SET/GET subcommand и `ParameterMetaV3` с `ParameterCodecIdV3.SLIDER`, `WidgetKindV3.SLIDER`, адресом master-устройства и нулевым offset. Только enum протокола сохраняет заданные прошивкой имена `PINCH_*`; ключи, локализация и UI описывают глобальное закрытое положение пальцев. Это позволяет существующим Android/iOS-слайдерам, состоянию и механизму профилей работать без специальных веток и не распространяет транспортную терминологию в presentation-слой.

Альтернатива — создать составную модель из двух значений. Она отвергнута: прошивка предоставляет независимые команды, а составная модель потребовала бы лишней координации обновлений и увеличила риск перезаписи второго параметра.

### 2. Переиспользовать однобайтовый slider codec и ограничить UI диапазоном `0…100`

SET-команда кодируется существующим коротким V3-пакетом со scalar-значением в одном байте; GET-ответ разбирается общим slider codec. Ограничение `0…100` задаётся декларацией каждого виджета, шаг остаётся `1`, `unitLabel` не задаётся. Значение является абсолютной долей закрытия: `0` соответствует полностью открытому, `100` — максимально закрытому положению.

Альтернатива — новый процентный codec. Она отвергнута как дублирование: процент здесь является смыслом значения, но не отдельным wire-типом или форматом отображения.

### 3. Добавить маршруты SET→GET и GET-response для каждого параметра

`WidgetCommandBridgeV3` должен преобразовывать SET metadata в соответствующий GET при запросе текущего значения и нормализовать GET в SET при записи. `WidgetResponseRoutesV3` должен независимо направлять ответы `0x45` и `0x47` в общий scalar codec и slider update flow.

Альтернатива — разбирать команды непосредственно в платформенных ViewModel/адаптерах. Она отвергнута, поскольку нарушает общий KMM-контракт и создаёт расхождение Android/iOS.

### 4. Декларировать виджеты только в standard V3 generator

Два `SliderParameterWidgetSStruct` с `display = 4`, диапазоном `0…100` и локализованными заголовками «Закрытое положение большого пальца» и «Закрытое положение указательного/среднего пальцев» добавляются в служебный блок standard V3. `generatedHardcodeWidgetsINDY3()` остаётся без изменений.

Это сохраняет существующее разделение профилей. Альтернатива — добавить runtime-фильтрацию после общей генерации — усложнила бы опубликованный список и создала риск утечки неподдерживаемых параметров в INDY3.

### 5. Расширить только standard V3 init-последовательности обеих платформ

Android и iOS добавляют два GET-запроса и ожидаемые response keys в standard V3 init. INDY3 builders не меняются. Общие enum, metadata и response routes остаются единым источником протокольных идентификаторов; платформенные init builders отвечают только за планирование своего BLE-транспорта.

Полная унификация всех init builders не входит в изменение: она затронула бы большой несвязанный набор команд. Для снижения дублирования новые записи должны собираться из общих enum/metadata, а parity закрепляется тестами.

### 6. Сохранить глобальную семантику изменения и стандартное поведение профилей

Android отправляет SET после окончания drag и через существующий debounce кнопок; iOS использует текущую commit-семантику `SliderListItemViewModelV3`. После локального изменения обновляются typed store и существующее профильное хранилище так же, как для остальных scalar-слайдеров. Ключи состояния не содержат gesture id, поэтому переключение жеста не создаёт копию значений и не меняет UI. При следующем подключении GET-ответ устройства остаётся источником фактического состояния.

## Risks / Trade-offs

- [Фактическая прошивка может кодировать payload иначе, чем существующий однобайтовый scalar] → до приёмки проверить сырые пакеты SET/GET на поддерживаемом V3 или согласованном BLE-эмуляторе; при расхождении заменить только codec/packet builder, не меняя UI-контракт.
- [Android и iOS имеют отдельные init builders] → добавить симметричные тесты состава запросов и expected response keys, включая отрицательную проверку INDY3.
- [Оптимистичное локальное обновление может временно отличаться от устройства при неуспешной записи] → сохранить текущую семантику V3-слайдеров и проверять фактическое значение при следующем GET/переподключении; отдельный механизм ACK не вводится.
- [Новые metadata автоматически входят в профили настроек] → покрыть round-trip профиля тестом для обоих независимых параметров и убедиться, что каждый восстанавливается своей SET-командой.
- [Имя firmware-команд `PINCH_*` может ошибочно вернуть привязку UI к одному жесту] → ограничить это имя протокольным enum и тестами закрепить нейтральные ключи/заголовки и отсутствие gesture id в состоянии.
- [Длинные локализованные заголовки могут переноситься на небольших экранах] → проверить существующие V3 slider cells на Android/iOS в русской и английской локалях без создания отдельного layout.

## Migration Plan

1. Добавить общие протокольные определения, нейтральные domain metadata, codec routes, строки и служебные standard V3 widget declarations.
2. Расширить standard V3 init на Android и iOS, не меняя INDY3.
3. Добавить unit-тесты пакетов, глобальной маршрутизации без gesture id, служебного набора виджетов, профилей и platform parity.
4. Выполнить UI smoke-проверки обеих платформ и BLE-проверку значений `0`, промежуточного значения и `100` на актуальной V3-прошивке.
5. При несовместимости прошивки откатить публикацию двух виджетов вместе с init-запросами; существующие V3 и INDY3 настройки остаются совместимыми.
