# Проверка versions/v3: Clean Architecture, MVVM и MVI

Дата: 2026-09-16. Область: весь пакет `app/.../ubi4/versions/v3`, его
Android-подключения и тесты. Это проверка уже перенесённых сценариев, а не
объявление завершённой миграции всего приложения. Состав Gradle-модулей сохранён.

## Обязательный контракт

`UI Action → экранная ViewModel → UseCase → domain Repository → data implementation`.
Чтение и подписки также проходят через UseCase. Результаты ViewModel преобразует
в неизменяемый `UiState`, который Fragment отображает. `render` не отправляет команд.
В presentation UseCase вызывает только ViewModel; фабрики собирают зависимости в `di`.

Это выбранное для проекта строгое правило. Само по себе использование domain-интерфейса
репозитория в presentation не запрещается всеми вариантами Clean Architecture,
но в этом проекте оно больше не допускается.

## Найдено и исправлено

| Место | Было | Стало |
| --- | --- | --- |
| `V3SliderSettingsStateHolder` | Сам подписывался на repository, читал значения и вызывал UseCase | Только черновики, доступность, UI-состояние и debounce; `onWriteRequested` сообщает владельцу о сохранении |
| `V3SensorsPlotController` | Второй координатор чтения, подписок и UseCase внутри presentation | Удалён; подписки, редактирование и запись принадлежат `V3SensorsViewModel`; `V3PlotSmoother` остаётся чистой обработкой отображения |
| Пять ViewModel | Прямые чтения репозиториев и их потоков | Только Get/Observe/командные UseCase; синхронная проверка доступности перед действием сохранена |
| Нейтральная Slider ViewModel | Действия слайдера и отдельные lifecycle-методы | Единственная точка входа `onAction(V3SliderSettingsAction)` для lifecycle и пользовательского ввода |
| Профили настроек | ViewModel синхронизировала локальный кэш выбора | `LoadSettingsProfilesUseCaseV3` читает профили и обновляет кэш после проверки отмены и актуальности serial; `GetSettingsProfilesUseCaseV3` остаётся чистым чтением |
| Источники состава экранов | Читали MAC, профиль, глобальные сигналы и признак восстановления | Контекст и сигнал обновления получает ViewModel через UseCase; источники получают профиль аргументом и готовят только UI |
| Сборка зависимостей | Factory находились в presentation | Пять Factory перенесены в `versions/v3/di`; конструкторы ViewModel вызываются с именованными аргументами |
| Domain-правила параметров | Использовали общий служебный набор `ConstantManagerUBI4` с UI и протокольными идентификаторами | Узкий `V3ParameterKeys`; соответствие неизменённым shared-ключам проверяется тестом |

Обработка кадров графика сохраняет интервал 25 мс. Проверка паузы выполняется
отдельным лёгким UseCase: значения порогов не декодируются на каждом кадре.
При чтении жестов ViewModel получает один согласованный снимок вместо повторного
чтения активного жеста и группы.

## Границы совместимости

`shared` является модулем, а не отдельным слоем. Существующий `DataFactory`
фильтрует и сортирует уже созданные описания, подставляет подписи и создаёт UI Items.
Эта работа относится к presentation, несмотря на историческое имя папки `data`.
Поэтому UI-состав и старые widget-структуры **не перенесены в domain**.

Три `DataFactoryV3*WidgetsSource` и три `V3*WidgetMapper` сохраняют связь с этим
общим UI-кодом и прежними Android-адаптерами. Они могут использовать `DataFactory`,
структуры UI и registry метаданных. Они больше не читают MAC, состояние подключения,
preferences и не подписываются на глобальные потоки. Эти шесть точек явно перечислены
в архитектурной проверке; расширять их обязанности нельзя. Замена общей подготовки UI
остаётся частью этапа D, удаления оставшегося старого кода — соответствующих шагов плана.

Чистый KMM enum `V3DeviceProfile` используется повторно. Классификатор устройства
не копируется. Строковые ключи domain сопоставимы с существующим протоколом;
проверка равенства не позволяет изменить их незаметно.

## Что проверяется автоматически

`V3ArchitectureTest` входит в обычный `:app:testDebugUnitTest` и проверяет:

- независимость domain от Android, data, presentation и DI;
- отсутствие зависимости data от presentation и ViewModel;
- отсутствие Repository и создания UseCase в presentation;
- вызов UseCase только из ViewModel;
- единственный вход `onAction` и read-only `uiState` у каждой ViewModel;
- отсутствие инфраструктуры и изменяемых потоков в UiState/Action;
- ограниченные точки совместимости с общим UI;
- соответствие domain-ключей существующим shared-идентификаторам.

Это проверки исходных зависимостей и публичного контракта, а не доказательство всех
возможных свойств архитектуры. Поведение дополнительно проверяется существующими
тестами экранов, domain и data. Добавлены сценарии загрузки профилей без применения,
смены устройства и запоздалого результата после отмены.

Правила для следующих изменений закреплены в
`app/src/main/java/com/bailout/stickk/ubi4/versions/v3/AGENTS.md`.

## Верификация

515 модульных app-тестов прошли без ошибок и пропусков: прежние 504,
8 архитектурных проверок и 3 проверки загрузки профилей. Обычные debug/release
APK и APK инструментальных тестов собраны. Лог: `/tmp/v3-clean-architecture-final.log`.

На Android-эмуляторе прошли 4 UI-сценария: активный жест и группа обычного V3,
скрытая вкладка INDY3, Service/калибровка обоих вариантов с перехватом всех BLE-команд.
Лог: `/tmp/v3-clean-architecture-emulator.log`. Для эмулятора использована отдельная
тестовая копия: установленная основная подписана другим ключом и сохранена.
После проверки обычный debug APK восстановлен в стандартной выходной папке
(`/tmp/v3-clean-normal-debug.log`). Реальный BLE и графический драйвер Samsung
этим прогоном не проверялись; приложение на телефоне не обновлялось.

На физическом телефоне не запускать EMU: пользователь использует реальное устройство 00001.

## Оставшаяся миграция

Вне этой проверки остаются ещё не перенесённые операции старых Fragment/адаптеров,
включая редактирование группы ротации C1.2.2 и остальное состояние жестов C1.3,
координация Activity/Base на C4 и внутренние обязанности общего KMM-кода на D.
Это не исключения, разрешающие добавлять новые обходы в `versions/v3`.
Следующий функциональный шаг по плану — C1.2.2; текущая проверка новых сценариев не добавляет.
