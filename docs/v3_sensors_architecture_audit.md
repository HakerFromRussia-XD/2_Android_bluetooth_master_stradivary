# Проверка архитектурных границ Sensors V3 — B1.4

Актуальные границы слоёв после проверки 2026-09-16: [аудит MVVM + MVI](v3_clean_architecture_audit.md).
Описания отдельных этапов ниже отражают историю переноса.


Дата: 2026-09-14. Основной порядок работ — [план](ubi4_v3_clean_architecture_plan.md).
B1 завершает перенос поведения Sensors на MVVM и UiState/Action. Общая
инфраструктура приложения и перенос domain в shared остаются отдельными этапами.

## Проверенные границы

| Область | Текущий путь и ответственность |
| --- | --- |
| Состав | DataFactoryV3SensorsWidgetsSource → типизированный снимок → V3SensorsViewModel → UiState.widgets → Fragment. Оба генератора дают Plot, два Slider чувствительности и Buttons; проверены STANDARD_V3/INDY3 и ru/en. |
| Slider | Адаптер → Fragment → экранная ViewModel → V3SliderSettingsStateHolder → SetSliderValueUseCaseV3 → Repository. Диапазоны определяет domain; черновики и задержка отправки принадлежат presentation. |
| Plot | Repository отдаёт отсчёты и пороги. Controller готовит кадры и черновик, адаптер рисует график. EditPlotThresholdUseCaseV3 меняет выбранный порог, SetPlotThresholdsUseCaseV3 передаёт пару для записи. |
| Кнопки | SensorsButtonsDelegateAdapterV3 передаёт события; ViewModel хранит принятые нажатия, UseCase/Repository выполняют OPEN/CLOSE/STOP. Адаптер не обращается к BLE или store. |
| Обновление | RefreshRequested → ViewModel → UseCase → Repository → существующая синхронизация. Локальная анимация свайпа не объявляет BLE готовым. |
| Lifecycle | Fragment собирает состояние в STARTED. Уход отменяет отложенные отправки Slider, подписки/таймер Plot и завершает принятые нажатия. Rebind/recycle/destroy освобождают обработчики View. |

В ViewModel и трёх делегатах Sensors нет обращения к Activity, BLEController,
глобальным stores или DataFactory. Domain Sensors не зависит от Android View,
Fragment, data-реализаций или UI-структур shared. Сборка зависимостей в фабрике
и BaseWidgetsFragment остаётся точкой подключения к существующему приложению.

Sensors не создаёт вторую Slider ViewModel через Base: набор
v3SliderParameterKeys у него пустой, действия переопределены для экранной модели.
Новый кнопочный адаптер выбирается первым только для display=1. Калибровка
Service display=4 остаётся в ButtonsDelegateAdapterV3.

Текущая навигация из Sensors на другие вкладки, аккаунт, помощь и Service
использует replace; представление Sensors останавливается/уничтожается.
Ветки hide/add в Activity относятся к другим вложенным маршрутам. Изменять
общую навигацию для этой проверки не потребовалось.

## Исправление по результату проверки

После ViewModelStore.clear() запоздалый SliderChangeCommitted мог вызвать
Repository: общий Slider controller ещё считал себя активным, хотя его scope
уже был отменён. Новый регрессионный тест воспроизвёл отправку.

Вход V3SensorsViewModel.onAction теперь игнорирует все действия после отмены
viewModelScope. Проверены commit, изменение черновика, шаг +/- и повторный
ViewAttached; они больше не отправляют данные и не меняют состояние уничтоженной
модели. Дополнена проверка, что позднее подключение не оживляет Plot. Проверки
кнопок и refresh после очистки сохранены. Общий Slider controller других экранов
в этом шаге не изменён.

## Что остаётся в следующих этапах

| Остаточная связь | Почему сохранена / этап |
| --- | --- |
| DataFactoryV3SensorsWidgetsSource и mapper с метаданными shared | Мост подготовки UI без изменения генераторов и API iOS. Разделение обязанностей — D2. |
| UiState.isInterfaceV3Activated во Fragment | Выбор существующего пути V3 или UBI4; глобальное определение версии — C4. |
| onResume → UiState.updateFlow и общая работа Base с notifyDataSetChanged/именами жестов | Сохранено прежнее уведомление и поведение базового класса; сокращение общих обязанностей — C4. V3-значения из этого события не записываются. |
| DataFactory и updateFlow внутри bindUbi4Widgets | Динамический UBI4 пока остаётся на прежнем пути до E2. |
| Фабрики Repository в Base, MainActivity.main, SyncProgressDialog и очередь | Точки подключения к существующему транспорту; владелец общей синхронизации — Activity/BLEController. Выделение инфраструктуры — C4. |
| Реализации Repository поверх shared stores/кодеков/профилей | Внешние данные уже закрыты domain-контрактами; внутреннее разделение shared — D2. |
| Domain физически в app | Платформенно независимый код переносится в shared на D1. |

Контракты записи Slider/порогов пока не принимают идентификатор сессии
подключения. Проверка смены состава сбрасывает черновики; проверка связи уже
поставленных команд с транспортной сессией относится к C4. Для кнопок
перед постановкой проверяется текущий MAC; алгоритм очереди не изменён.

B1 не означает завершение C4/D или полной проверки физических команд на обоих
устройствах. Реальные OPEN/CLOSE и изменение параметров, а также физический
INDY3 остаются в проверке E1. UI, парсеры, shared, iOS, протоколы и Gradle-модули
в B1.4 не менялись.
