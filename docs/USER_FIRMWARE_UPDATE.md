# Пользовательское обновление V3

## Источник

`assembly.json` читается из корня существующего публичного каталога Яндекс Диска.
Формат assembly из `firmware_json_spec.md` сохранён: `format`, `kind`, `created_at`,
`created_by`, `label`, `product`, `config_version`, `modules`, `checksum`.
Элемент `modules` содержит только `address`, `name`, `file`, `sha256`.
`file` — относительный путь ZIP, например `GUI/GUI_Module_v0.5.2+1_09.zip`.
Адрес — десятичное число; SHA-256 — 64 шестнадцатеричных символа в нижнем регистре.
Документ проверяется по checksum: удалить checksum, рекурсивно отсортировать ключи,
сериализовать без пробелов/ASCII-экранирования и завершающего перевода строки, SHA-256 UTF-8.

`version`/`subversion` остаются свойствами схемы слота в документе модуля.
Единственное дополнение к этой структуре — `quickfiks` (модель FirmwareModuleSlotVersion).
Эти поля не переносятся в modules[] и не используются как версия основной программы.
Запись слотов/профилей и переход DFU на новый JSON в эту реализацию не входят.

Целевая версия читается из существующего FW_ini.ini внутри указанного ZIP:
`FwMajorVersion.FwMinorVersion.FwQuickFix`. Поэтому архивы присутствующих плат
автоматически скачиваются и проверяются до предложения обновления. Проверяются
SHA-256, распаковка, тип основной программы и CRC бинарника из текущего дескриптора.
Сервисный каталог, выбор файлов и существующий DFU v1/v2 сохранены.
Манифест/архивы эта реализация в облако не публикует.

## Сценарий

Только пользовательская роль (2), после соединения V3 и при переключении роли.
Кандидаты — присутствующие платы с версией ниже целевой. Неизвестная версия
не превращается в ноль. Порядок берётся из modules[], FAM (0) переносится в конец.

Offer → подготовка всех файлов → последовательные DFU → проверка каждой платы → завершение.
Offer, прогресс, ожидание и завершение блокируют взаимодействие с приложением.
Установка запускается один раз нажатием «Установить обновление», итог закрывается «ОК».
Русские/английские строки общие в Moko KMM.

После возврата DFU независимо от результата повторно читаются GET_RUN_PROGRAM_TYPE
и SUB_DEVICE_MANAGER. MAIN + целевая версия завершают шаг. Загрузчик + известная
нецелевая версия немедленно запускают новую полную попытку из загрузчика.
MAIN с нецелевой версией, загрузчик с целевой версией и неизвестная версия не являются
подтверждённым успехом: остаётся блокирующее ожидание нового события состояния.
Нет таймеров задержки между попытками и ограничения их числа. Таймауты ответа
BLE и внутренние тайминги существующих транспортов DFU сохранены.

Потеря BLE ожидает возврата того же устройства. Проблемы сети/файлов повторно
проверяются по событиям доступности сети, соединения и возвращения приложения.
Неподходящий ZIP не отправляется. После всей очереди возобновляется обычная синхронизация.

## Возобновление

Журнал хранится в каталоге приложения user_firmware, отдельно по идентификатору
BLE-устройства. Он фиксирует адреса, целевые версии, пути и хеши архивов, завершённые
и начатые шаги. Согласие сохраняется до первой записи. Завершённые шаги пропускаются;
незавершённый сначала проверяется по свежим ответам BLE. Даже если приложение
завершилось после успешного DFU, но до записи результата в журнал, повторной записи
не будет при подтверждённых MAIN и целевой версии. Итоговое ОК очищает журнал.

## Проверки текущего этапа

Новые общие и JVM-тесты проверяют выбор плат, неизвестные версии, повреждённые
контрольные суммы и архивы, сетевые ошибки, восстановление журнала, отсутствие
повторной записи завершённых шагов и блокирующие состояния интерфейса.
Новые UIKit-тесты UserFirmwareProgressViewTests проверяют перехват нажатий вне
панели и отсутствие действий закрытия во время прогресса/ожидания.

Отдельный запуск тестов функции (старый BindingGroupV3Test не компилируется из-за
отсутствующего BINDING_GROUP_FLOW):

```sh
./gradlew :shared:testDebugUnitTest --tests '*UserFirmware*' \
  -I tools/user_firmware_tests.init.gradle --no-configuration-cache
./gradlew :app:compileDebugKotlinAndroid
```

Тестирование реальных плат — следующий этап по отдельным инструкциям пользователя.
