# V3: обязательные границы Clean Architecture, MVVM и MVI

- SOLID, KISS, DRY: выделять классы по самостоятельной ответственности, а не по
  количеству методов. Сначала упрощать существующие классы и удалять перенесённые
  дубли. Не добавлять сквозные обёртки/базовые классы ради формального разделения.
  Одинаковые правила объединять, похожие сценарии с разным поведением не смешивать.

- По указанию пользователя от 2026-09-22 BLEController исключён из дальнейших
  изменений. Не переносить его методы, не менять внутреннюю реализацию,
  публичные контракты и поведение ради архитектуры UI. Использовать текущий
  контроллер через существующие границы; требующий его изменения шаг отложить.

- AdvancedFragment исключён из дальнейшего рефакторинга по прямому указанию
  пользователя. Не менять сам экран, его Slider binder, lifecycle, маршруты
  и связанную сборку зависимостей ради разгрузки BaseWidgetsFragment.

- По решению пользователя формирование виджетов сохраняется в
  generatedHardcodeWidgets/generatedHardcodeWidgetsINDY3 с display и позицией.
  Замена на отдельные или единый Android-каталог отменена пользователем.
  Сохранять DataFactory и DataFactoryV3*WidgetsSource как границу совместимости;
  не возобновлять замену состава виджетов без нового явного запроса.

- Область задачи — только V3 (STANDARD_V3 и INDY3). По уточнению пользователя
  2026-09-16 рефакторинг UBI4 исключён, в том числе после завершения V3.
  Общие Fragment, DataFactory, Activity, ресурсы и инфраструктура имеют UBI4-потребителей:
  не перерабатывать их целиком ради V3. Сохранять UBI4-пути, ключи, данные и поведение;
  выделять обязанности V3. Наличие общего файла не разрешает переносить логику UBI4.
  Пользователь разрешил изменения общих файлов при сохранении логики приложения
  и работоспособности UBI4. Для каждой общей правки проверять обе ветки и потребителей;
  отсутствие проверки не считать подтверждением совместимости.

- При переносе сохранять существующую логику: правила, лимиты, порядок и семантику
  сохранения. Не исправлять замеченные особенности и не добавлять новые бизнес-правила
  в рамках архитектурного рефакторинга без отдельного запроса пользователя.

- UI передаёт Action экранной ViewModel и отображает её неизменяемый UiState.
  Не записывать параметры при render/bind. ViewModel — владелец состояния экрана.
- Только ViewModel вызывает UseCase в presentation. Чтение, подписки и запись
  проходят через UseCase; прямые зависимости presentation от repository запрещены.
- StateHolder, smoother и mapper обрабатывают UI-значения. Они не зависят от
  Repository, UseCase, BLE, хранилищ, глобального состояния устройства или Activity.
  StateHolder сообщает ViewModel о намерении сохранить значение, а не сохраняет сам.
- Domain содержит правила, модели устройства, UseCase и интерфейсы репозиториев.
  Он не зависит от Android, data, presentation, DI, DataFactory или UI widget-структур.
  Общий чистый enum V3DeviceProfile из KMM разрешён; не дублировать классификатор.
- Data реализует domain-контракты. Только здесь обращаться к ParameterStore,
  WidgetRepoProvider, preferences, Room, сети и существующему BLE-коду.
- Ручная сборка зависимостей находится в di. Не помещать фабрики зависимостей
  обратно в presentation и не вводить DI-фреймворк без необходимости.
- Существующие DataFactoryV3*WidgetsSource и V3*WidgetMapper — ограниченная
  граница совместимости с общей подготовкой UI и прежними Android-адаптерами.
  В них допустимы DataFactory, неизменяемые описания виджетов и registry метаданных.
  Они не читают адрес/профиль устройства, interaction flags и preferences,
  не подписываются на глобальные потоки и не отправляют команды. Контекст устройства
  получает ViewModel через GetDeviceSessionUseCaseV3/ObserveDeviceSessionChangesUseCaseV3.
  Не переносить UI-состав, локализацию или List<Any> в domain ради обхода этой границы.
- Сохранять отмену отложенных записей при STOP, смене устройства и блокировке.
  Обработчики после очистки ViewModel не должны возобновлять работу.
- Проверять V3ArchitectureTest и поведенческие app-тесты после изменения границ.
  Не ослаблять архитектурные проверки, чтобы пропустить запрещённую зависимость.
- UI, парсеры, UBI4, iOS и папки by_Misha/by_Radeon не менять в рамках этой проверки.
  На физическом телефоне использовать реальное устройство 00001; EMU — только
  на Android-эмуляторе. Не отправлять команды движения/калибровки для проверки архитектуры.
